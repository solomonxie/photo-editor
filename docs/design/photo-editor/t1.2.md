# T1.2 Render engine

It turns an `EditDocument` into pixels, fast on screen and complete on export.

```
                      ┌── proxy (long edge = screen px × 1.0) ──▶ MTKView drawable
original ─decode─▶ CIImage ─ graph(doc) ─┤
                      └── full res (tiled)  ──────────────────▶ HEIC/JPEG/PNG
```

## Rules

- **One `CIContext`** for the app: `MTLCreateSystemDefaultDevice`, working
  format `RGBAh`, working space extended linear P3, `cacheIntermediates: false`
  for export and `true` for preview.
- **Proxy is decoded once** per open (`CGImageSourceCreateThumbnailAtIndex`,
  `kCGImageSourceThumbnailMaxPixelSize`), then kept as a `CIImage` backed by an
  `MTLTexture`. Sliders never touch the 48 MP original.
- **Embedded thumbnail first** (HEIC has one) → shows in < 100 ms, then the proxy swaps in.
- **Graph build is cheap and re-run on every change.** `CIImage` is lazy, and
  Core Image fuses the kernels. No manual caching of intermediate images, except
  expensive ones that are parameter-independent:
  - Vision masks and heal patches go in an `NSCache` keyed by asset name.
- **Render on demand.** The canvas asks for a frame when the document or the
  viewport changes. Coalesce to the display link, so a frame is dropped rather than queued.
- **Export:** `CIContext.heifRepresentation` / `jpegRepresentation` /
  `pngRepresentation` on the full graph. Tiled automatically by CI. Run it on a
  background task with progress via row-band rendering, cancellable.
- **HDR:** if the source has a gain map, read it with `CIImage(… .expandToHDR)`.
  EDR drawable on capable displays, and write the gain map back on HEIC export.
- **Custom kernels** are `.ci.metal` → `CIKernel(functionName:fromMetalLibraryData:)`.
  Loaded once.

## Instrumentation

- `os_signpost` around graph build, proxy render and export.
- T1.5 reads these against the DESIGN targets.
